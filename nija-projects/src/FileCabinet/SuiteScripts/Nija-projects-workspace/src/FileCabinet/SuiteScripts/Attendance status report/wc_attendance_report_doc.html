Overview

The WinStar Attendance Portal Suitelet aggregates and renders monthly attendance records for employees based on Subsidiary and Pay Group configurations. The script displays statuses (Present, Absent, Leave, Swipe Missing, Week Off) along with daily work/OT hours and project information.

The Problem: 5,000-Row Truncation

The Suitelet script initially used query.runSuiteQL().asMappedResults() to fetch employee logs. While this standard SuiteSQL API works well for small datasets, it contains a hard NetSuite governance limit of **5,000 results** per call. Any records beyond 5,000 are discarded.

Impact of the 5,000 Limit

When loading July 2026, the database had 7,113 total logs. Because the query was sorted by name (ORDER BY emp_name), the query cut off exactly at the 5,000th record. The last 2,113 rows were completely lost, which caused employees later in the alphabet (S to Z) to disappear from the report.

The Solution: SuiteQL Pagination

To bypass the 5,000-row limit, the code was updated to use query.runSuiteQLPaged(). This native SuiteScript 2.x API slices the results into distinct, paginated blocks of 1,000 rows, allowing us to safely retrieve datasets up to 100,000 rows.

Before (Broken - Limits to 5,000) ❌ 
// Standard SuiteQL execution
var results = query.runSuiteQL({
    query: sql,
    params: [subId, start, end]
}).asMappedResults();

log.debug('Results', results.length); 
// Hard truncated to exactly 5000
After (Fixed - Paginated) ✓ 
// Paged execution loop
var results = [];
try {
    var pagedResults = query.runSuiteQLPaged({
        query: sql,
        params: [subId, start, end],
        pageSize: 1000
    });
    pagedResults.pageRanges.forEach(function (pageRange) {
        var page = pagedResults.fetch({ 
            index: pageRange.index 
        });
        results = results.concat(page.data.asMappedResults());
    });
} catch (queryErr) {
    // Fallback safe trigger
    results = query.runSuiteQL({ ... }).asMappedResults();
}
Outcome

The record count successfully increased from 5,000 to 7,113, and the number of active rendering employees in the Suitelet climbed from ~160 to **230 employees**, showing alphabetical listings through the letter Z.

Join Conditions

If an employee record exists, but has no parent attendance record or zero daily logs within the selected date range, they will be excluded from the results.

Troubleshooting Missing Employees

To debug the remaining 6 missing employees, we added a diagnostic check that runs comparison checks on active employees in the selected subsidiary and logs the status to the execution log.

Diagnostic Output Status Root Cause Resolution Action
Missing Parent Attendance Record The parent custom record CUSTOMRECORD_NJT_EMP_DAILY_ATTENDANCE has not been created for this employee. Create a parent attendance header record for the employee in NetSuite.
Parent record exists, but has 0 daily logs The parent record exists, but no children detail logs (CUSTOMRECORD_NJT_EMP_DAILY_ATTEN_CH) are logged in the wage period date range. Verify that the daily attendance logs are imported or run for the selected month.
Has X logs in date range. Check for code mismatch. Logs exist in the database, but the employee code or name contains mismatching spaces/data fields that cause mapping failures. Check that the employee code field (custentity_hris_empcode) matches the parent lookup details.
