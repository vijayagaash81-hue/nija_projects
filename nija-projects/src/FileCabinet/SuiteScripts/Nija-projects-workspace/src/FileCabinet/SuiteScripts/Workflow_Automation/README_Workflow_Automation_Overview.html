Dynamic Approval Engine

Unified Multi-Level Approval Framework

Workflow Framework Overview

The Workflow_Automation directory implements a metadata-driven, multi-level approval engine. Instead of hardcoding unique approval paths for each custom transaction (e.g. NOCs, Travel Requests, Expense Claims, Passport Requests), all workflow folders execute the exact same core routing logic based on dynamic mappings.

1. Setup Custom Records

The approval sequence levels and histories are stored inside three dedicated custom records:

  • Approval Setup (customrecord_approval_setup): Defines the main approval routing criteria, linking a NetSuite record type (such as customrecord_njt_noc) to an active Department and enabling email alert settings.
  • Approval Setup Detail (customrecord_approval_setup_detail): Represents individual approval levels (Level 1, 2, 3, etc.). Defines whether the level is assigned to a specific Employee ID or to a NetSuite Role ID.
  • Approval History (customrecord_approval_history): Records an audit trail of every workflow action (Submitted, Approved, Rejected, Resubmitted) capturing timestamps, comments, and the executor's identity.

2. Script Framework

The framework utilizes a single shared Client Script, a single Suitelet Script, and a standard User Event configuration script per custom transaction:

User Event Script
Dynamic Form Injectors (e.g. njt_workflow_noc.js, njt_workflow_pr.js) These UE scripts are registered on individual transaction records. During beforeLoad, they dynamically render the approval header banner (Approved/Pending Approval/Rejected), identify the current user's approval rights, and attach the action buttons. During afterSubmit, they automatically assign the Level 1 approver upon record creation.
Client Script
approval_cs.js Attached dynamically by the User Event scripts. It listens to action button clicks (Approve, Reject, Submit, Resubmit) and prompts the user for rejection reasons. Then, it forwards the parameters to the Suitelet processing engine.
Suitelet Script
njt_workflo_sl.js The central background action handler. It processes transaction states: registers approvals, increments routing levels, fires HTML email alerts (to next approvers or requestors), writes history audits, and redirects the browser back to the updated transaction page.

3. Detailed Execution Flow

1
Creation & Level 1 Setup

When a record is created, the User Event script fires on afterSubmit, matches the record type and department to an active Approval Setup, finds the Level 1 approver from the setup details, maps them to the record, and records a 'Submitted' audit history.

2
Approve Action

When the next approver clicks Approve, the Client script routes the action to the Suitelet. The Suitelet loads the approval setup details, checks for a next level (e.g. Level 2). If found, it updates the record's next approver fields and sends an email. If no further levels exist, it sets the status to Approved.

3
Reject & Resubmit Action

If the approver clicks Reject, the Client script prompts for a rejection reason. The Suitelet saves the reason, clears the next approver fields, and sets the status to Rejected. If the setup record permits resubmission, a Resubmit for Approval button is displayed to the requestor to restart the workflow at Level 1.
